# Supabase setup (free tier)

This starter runs as a polished frontend without Supabase. Community reviews are saved in the current browser as a local demo. To make reviews shared across visitors and enable accounts, connect a free Supabase project.

## 1. Create project
1. Create a project at https://supabase.com/ and choose the Free plan.
2. In Project Settings → API, copy the Project URL and anon/publishable key.
3. Copy `.env.example` to `.env` and fill in those two values. Never use the `service_role` key in a browser app.

## 2. Create the reviews table
Run this SQL in Supabase → SQL Editor:

```sql
create table if not exists public.reviews (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 60),
  destination text not null,
  rating int not null check (rating between 1 and 5),
  body text not null check (char_length(body) between 1 and 1200),
  status text not null default 'pending' check (status in ('pending','approved','rejected')),
  created_at timestamptz not null default now()
);

alter table public.reviews enable row level security;

-- Anyone can submit a review, but it is always pending moderation.
create policy "Visitors can submit pending reviews"
on public.reviews for insert
to anon, authenticated
with check (status = 'pending');

-- Visitors can only read approved reviews.
create policy "Visitors can read approved reviews"
on public.reviews for select
to anon, authenticated
using (status = 'approved');
```

## 3. Moderation
Review and approve submissions from Supabase Table Editor. Change `status` to `approved` to publish or `rejected` to hide. For production, create a protected admin workflow; do not expose admin/service credentials in frontend code.

## 4. Add authentication and media storage later
- Enable Supabase Auth providers you want (email magic link is a good simple option).
- Create a private admin role and server-side moderation workflow before allowing public edits.
- For media, start with compressed WebP photos and external video embeds. Supabase Free storage is limited, so do not upload large video files without checking current quotas.
- Add storage bucket policies that restrict upload to authenticated admins only. Public visitor downloads should be limited to media explicitly marked public.

## 5. Local development
```bash
npm install
npm run dev
```
Open the local URL printed by Vite.

## 6. Deploy to Netlify
1. Push this project to a GitHub repository.
2. In Netlify, import the repository.
3. Build command: `npm run build`; publish directory: `dist`.
4. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in Site configuration → Environment variables.
5. Deploy.

Free-plan quotas and terms can change. Check provider pricing before relying on any quota for a public media library.
